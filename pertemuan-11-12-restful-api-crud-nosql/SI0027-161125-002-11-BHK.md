# Bagian 1 - Konsep Dasar (01 / 06)

**Dari CRUD Sederhana ke API Siap Produksi**

## Review: Prinsip RESTful & Pemetaan Method HTTP

Pertemuan 3-4/6-7 telah membangun CRUD dasar. Pertemuan ini melengkapinya agar API siap dipakai pada aplikasi nyata dengan data yang banyak.

| Method | Endpoint | Status Sukses | Operasi Mongoose |
| --- | --- | --- | --- |
| GET | /mahasiswa | 200 OK | `Model.find(filter)` |
| GET | /mahasiswa/:id | 200 OK | `Model.findById(id)` |
| POST | /mahasiswa | 201 Created | `Model.create(data)` |
| PUT | /mahasiswa/:id | 200 OK | `Model.findByIdAndUpdate(id, data)` |
| DELETE | /mahasiswa/:id | 204 No Content | `Model.findByIdAndDelete(id)` |

---

## Tantangan API CRUD Ketika Data Bertambah Banyak

1. `GET /mahasiswa` tanpa batas dapat mengirim ribuan document sekaligus & membebani server maupun frontend
2. Pengguna sering perlu mencari data tertentu, mis. berdasarkan prodi, bukan mengambil seluruh data
3. Error yang tidak ditangani dengan rapi (mis. id salah format) dapat membuat server crash

---

## Format Response API yang Konsisten

### Response Sukses

- Data dikirim langsung sebagai JSON (array/object)
- Untuk data berjumlah banyak, sertakan info pagination (`total`, `page`, `limit`)
- Gunakan status code 2xx sesuai jenis operasi

### Response Gagal

- Format konsisten, mis. `{ message: 'pesan error' }`
- Gunakan status code 4xx untuk kesalahan client, 5xx untuk kesalahan server
- Jangan kirim detail teknis (stack trace) ke client pada mode production

# Bagian 2 - Konsep (02 / 06)

**Query Lanjutan & Error Handling**

## Filtering: Menyaring Data Berdasarkan Query Parameter

1. Query parameter pada URL (mis. `?prodi=SI`) dibaca lewat `req.query` pada Express
2. Nilai `req.query` disusun menjadi object filter, lalu diteruskan ke `Model.find(filter)`
3. Filter kosong (`{}`) berarti seluruh document diambil, seperti tanpa filtering

---

## Sorting & Pagination pada Mongoose

| Metode Query | Contoh Penulisan | Fungsi |
| --- | --- | --- |
| `.sort()` | `.sort({ nama: 1 })` | Mengurutkan hasil (1 = naik, -1 = turun) |
| `.skip()` | `.skip((page - 1) * limit)` | Melewati sejumlah document (halaman sebelumnya) |
| `.limit()` | `.limit(limit)` | Membatasi jumlah document yang dikembalikan |

---

## Projection: Memilih Field yang Dikembalikan

Projection membatasi field yang dikirim pada response, sehingga ukuran data lebih kecil dan data sensitif dapat disembunyikan.

| Contoh Penulisan | Fungsi |
| --- | --- |
| `.select('nama nim')` | Hanya mengembalikan field nama dan nim |
| `.select('-password')` | Mengembalikan seluruh field kecuali password |

---

## Error Handling Terpusat pada Express

1. Tanpa penanganan khusus, error pada fungsi async (mis. id salah format) dapat membuat Express diam / crash
2. Middleware error handling terpusat menangkap seluruh error di satu tempat, bukan try/catch berulang di setiap controller
3. Middleware error ditandai dengan 4 parameter: `(err, req, res, next)`, didaftarkan paling akhir setelah seluruh route

## Filtering Berdasarkan Query Parameter

`controllers/mahasiswaController.js`

```javascript
// GET /mahasiswa?prodi=Sistem+Informasi
exports.getAll = async (req, res) => {
  const filter = {};
  if (req.query.prodi) {
    filter.prodi = req.query.prodi;
  }
  const data = await Mahasiswa.find(filter);
  res.json(data);
};
```

---

## Sorting & Pagination

`controllers/mahasiswaController.js`

```javascript
// GET /mahasiswa?page=1&limit=10&sort=nama
exports.getAll = async (req, res) => {
  const page = parseInt(req.query.page) || 1;
  const limit = parseInt(req.query.limit) || 10;
  const sortField = req.query.sort || 'createdAt';

  const data = await Mahasiswa.find()
    .sort({ [sortField]: 1 })
    .skip((page - 1) * limit)
    .limit(limit);

  const total = await Mahasiswa.countDocuments();
  res.json({ data, page, limit, total });
};
```

---

## Projection dengan select()

`controllers/mahasiswaController.js`

```javascript
// GET /mahasiswa - hanya kirim field nama & nim
exports.getAll = async (req, res) => {
  const data = await Mahasiswa.find().select('nama nim');
  res.json(data);
};
```

---

## Menangkap Error Async dengan express-async-errors

`app.js` & controller

```javascript
// app.js - baris pertama, sebelum require express lain
require('express-async-errors');
const express = require('express');
const app = express();

// controller - error otomatis diteruskan ke middleware error
exports.getById = async (req, res) => {
  const data = await Mahasiswa.findById(req.params.id);
  if (!data) throw { status: 404, message: 'Tidak ditemukan' };
  res.json(data);
};
```

---

## Middleware Error Handling Terpusat

`middlewares/errorHandler.js` & `app.js`

```javascript
// middlewares/errorHandler.js
function errorHandler(err, req, res, next) {
  const status = err.status || 500;
  res.status(status).json({ message: err.message || 'Terjadi kesalahan' });
}
module.exports = errorHandler;

// app.js - didaftarkan PALING AKHIR, setelah seluruh route
app.use(errorHandler);
```

# Bagian 4 - Contoh Kasus (04 / 06)

**Studi Kasus & Kesalahan Umum**

## Studi Kasus: Endpoint Pencarian Mahasiswa per Prodi

Aplikasi akademik menampilkan daftar mahasiswa per prodi, 10 data per halaman, diurutkan berdasarkan nama, tanpa menampilkan field internal.

1. **Filtering** - `GET /mahasiswa?prodi=SI` menyaring hanya mahasiswa prodi SI
2. **Pagination** - `?page=1&limit=10` membatasi 10 data per permintaan
3. **Sorting & Projection** - `?sort=nama` dikombinasikan dengan `select('nama nim')`

---

## Kesalahan Umum pada API CRUD Berskala Besar

1. Tidak menerapkan pagination, sehingga `GET /mahasiswa` mengirim seluruh data sekaligus
2. `limit` diambil langsung dari `req.query` tanpa batas maksimum, rawan disalahgunakan (`?limit=999999`)
3. Error async tidak ditangkap, menyebabkan server berhenti merespons saat id tidak valid
4. Pesan error mentah (stack trace) dikirim langsung ke client, membocorkan detail internal server
